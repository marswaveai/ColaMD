# ColaMD 临时文档切换条 · 设计稿

> 目标：减少在多个文档之间切换时创建新窗口的成本，但不演变为 workspace / IDE。

---

## 01. 产品边界

### 要解决

- 在同一目录内来回读写几篇 Markdown 时，不必反复新开窗口。
- 已打开文档可一键切换；当前文档的保存状态仍然清楚。
- 对 Windows 尤其有利：减少额外窗口、完整编辑器初始化和重复渲染。

### 明确不做

- 不合并跨目录文档。
- 不支持拖拽排序。
- 不保存“工作区”或 Tab 会话。
- 不支持 Tab 分组、固定、拆分、预览模式。
- 不在启动时恢复 Tab；普通启动仍应是空白文档。

这不是 workspace。它只是当前窗口中的一小段、临时的文档切换历史。

---

## 02. 交互模型

### 文档从哪里进入切换条

仅两种入口：

1. 在左侧文件列表点开同目录文档。
2. 从「文件 → 打开」选择的文档，若与当前文档同目录。

来自另一目录的文件维持现状：新窗口打开。这样目录仍是 ColaMD 的天然上下文，也避免跨目录变成工作区。

### 容量

- 最多 **5 篇**。
- 打开第 6 篇时，自动移除最久未访问、且已经保存的那一篇。
- 若所有候选都有未保存修改，不自动移除；直接仍在新窗口打开，不能暗中丢内容。

### 关闭

- 每个非当前文档显示极弱的 `×`，hover 后才显现。
- 当前文档也可关闭；关闭后切到最近访问的文档。
- 有未保存内容时，沿用现有保存 / 不保存 / 取消确认。

### 退出

- 不记录 Tab 会话。
- 应用关闭后，这组文档消失；下次正常启动仍是空白。
- 最近文件仍按既有机制记录，这不是 Tab 恢复。

---

## 03. 视觉稿

切换条位于标题栏下、正文上；只在窗口中打开了两篇及以上文档时出现。

```text
┌──────────────────────────────────────────────────────────────────────┐
│                      project-notes.md   已编辑     ◌  ⌘/  ☷          │
├──────────────────────────────────────────────────────────────────────┤
│  ◉ project-notes.md   ×   │  todo.md   ×  │  changelog.md   ×        │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│                         # Project notes                              │
│                                                                      │
│                         ...                                          │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

### 尺寸与层级

| 元素 | 规则 |
|---|---|
| 切换条高度 | 30px |
| 背景 | 比正文背景略深/浅 2–4%，只用主题 token |
| 当前项 | 主题正文背景，底部 2px Cola 橙线 |
| 非当前项 | 低对比度文本，无卡片边框 |
| 文件名 | 单行省略，最多 180px |
| 未保存状态 | 不新增「未保存」文本；用标题后现有的「已编辑」状态 |
| 关闭 `×` | 默认透明，hover/focus 才显现 |
| 溢出 | 显示 `···`；打开一个小型列表，不横向滚动 |

禁止：彩色文件图标、每项永久关闭按钮、厚边框、类似浏览器的立体标签。

---

## 04. 键盘

- `⌘/Ctrl + 1…5`：切换第 1–5 篇临时文档。
- `⌘/Ctrl + W`：关闭当前临时文档；有未保存修改时沿用原确认。
- 不抢占 `⌘/Ctrl + Tab`：它可能与系统 / 浏览器习惯冲突，首版不碰。

---

## 05. 数据与实现原则

每个临时文档保留独立状态：

```ts
{
  path: string,
  content: string,
  dirty: boolean,
  scrollTop: number,
  sourceMode: boolean,
  lastVisitedAt: number
}
```

关键要求：

1. 切换时保存当前文档快照，不重新从磁盘读取当前内存内容。
2. 首版可以在切换时替换现有编辑器内容；不要求同时挂载 5 个 Milkdown 实例。
3. 切回时恢复该文档的滚动位置；第一次打开的文档仍从顶部开始。
4. 只有真正切走前的文档需要自动保存；不能因切换条重走菜单重建路径。
5. 外部文件变化沿用现有冲突保护；不允许一个 Tab 的 watcher 覆盖另一篇未保存文档。

---

## 06. 先做什么

### Phase 1：原型

- 只支持同目录。
- 最多 3 篇，而不是一开始就 5 篇。
- 点击切换、关闭、未保存确认、滚动恢复。
- 不添加快捷键、不做溢出菜单。

### Phase 2：验证后

- 调整至 5 篇。
- 加 `⌘/Ctrl + 1…5`。
- 加极简 `···` 文档列表。

### 不进入本功能

跨目录标签、拖拽排序、持久化工作区、重启恢复。这些应单独重新讨论。
