# 网页体验版（首页内嵌 + `/try/`）

一个纯网页的 ColaMD：能打字，能实时切换 12 个主题，用一份样张展示排版。

**它是什么**：同一个编辑器内核（Milkdown / ProseMirror）＋ 同一套主题 CSS，去掉桌面外壳后编成的静态页面。不是截图，也不是模拟。

**它不是什么**（刻意不做，见 design.md 的产品边界）：不读写本地文件、不做实时同步、没有标签页 / 文件列表 / 大纲 / 查找 / 导出 / 图表 / 公式 / 字体设置。网页版演示不了产品最核心的「本地优先」，所以页面上有一行固定的说明，并给下载桌面版的入口。

## 两种进入方式

| 地址 | 形态 |
| --- | --- |
| `/try/` | 独立页面，直接就是要打字的那种布局 |
| `/try/?embed=1` | 首页 hero 里的那一小块：只有一行提示 + 「全屏」按钮 |

首页 hero 的窗口里放的是一个 **iframe**，不是把编辑器编进首页。选 iframe 是为了两件事：主题变量和编辑器样式完全关在框里，不会和站点自己的 CSS 打架；点「全屏」只是把这个框拉满视口，**不换页面、不重载**，用户刚写的字还在。

## 全屏与独立页的形态：一个居中窗口

独立页 `/try/` 和从首页点开的全屏，都不是铺满屏幕，而是**一个居中的窗口**：

| 尺寸 | 值 |
| --- | --- |
| 窗口 | `min(920px, 100% - 48px)` × `min(720px, 100% - 48px)`，圆角 12px、1px 描边、投影 |
| 窗口里的正文列 | 沿用桌面版的 780px（`base.css` 里 `#editor .ProseMirror` 的 `max-width`），所以网页版和桌面版的行长一致 |
| 窗口外 | 主题背景色与文字色混合出的浅一档底色，让人看出这是一扇窗 |
| 滚动 | 页面本身不滚，滚的是窗口里的内容；滚动条用桌面版非 macOS 那套 6px 细条（`base.css` 里 `body.web-playground` 与 `body.platform-non-mac` 共用一组规则），系统浮层滚动条在窗口里太重 |
| 说明文字 | 在窗口外面（窗口下方居中），窗口里只留工具栏和正文 |
| 手机上（≤650px） | 去掉描边、圆角和投影，铺满整屏 |

首页内嵌那一小块不套这层窗口，因为站点的窗口已经是外壳了；这也是 `.try-shell` 平时是 `display: contents` 的原因。

## 首页与体验块怎么对话

两边都用 `postMessage`，各管一半，谁也不猜对方的状态：

| 消息 | 谁发给谁 | 含义 |
| --- | --- | --- |
| `colamd-try:ready` | 块 → 首页 | 我加载好了，把当前语言告诉我 |
| `colamd-try:ask-fullscreen` | 块 → 首页 | 我想全屏 / 想退出，你决定 |
| `colamd-try:set-fullscreen` | 首页 → 块 | 结果是这个，按它调整 |
| `colamd-try:set-lang` | 首页 → 块 | 站点切语言了，样张跟上来 |

首页收到请求后只做两件事：给 `<html>` 加 `try-fullscreen`（铺满视口 + 锁滚动），再把结论回给框。所以在框里按 Esc、在页面上按 Esc、点「退出全屏」，三条路都能回到原位。

## 为什么这么便宜

编辑核心对桌面能力的依赖只有四处，而且都是可选调用：

| 模块 | `window.electronAPI` 出现次数 |
| --- | --- |
| `src/renderer/editor/*.ts` | 4（其中 3 处带 `?.`） |
| `src/renderer/themes/*.ts` | 1 |

所以网页版**不需要 stub、不需要给渲染层打桩、不改一行桌面代码**：它是一个独立入口（`src/web/`），只 import 编辑器内核与主题 CSS。

首页要付的代价是实打实的：体验页的 bundle 会跟着首屏加载，JS 752KB（gzip 229KB）＋ CSS 61KB（gzip 15KB）。这是「首页直接能写」换来的，认了。

## 怎么构建与本地预览

```bash
npm run build:web        # 产出 dist-web/
npm run preview:web      # 体验页：http://localhost:4173/
                         # 首页形态：把 dist-web 拷到站点目录的 try/ 下再起静态服务
```

## 规矩

1. **同一份源码，永不分叉**：网页版 import 的是 `src/renderer` 里的编辑器与主题，改动只允许发生在 `src/web/`（页面外壳）里。想改编辑器行为，改桌面版用的那份。
2. **不把桌面能力搬进网页版**：`src/web/` 里不出现 `window.electronAPI`。要展示某个桌面能力，就在页面上说明它属于桌面版。
3. 页面自身的工具栏也用主题变量（`--bg-color` / `--chrome-bg-hover` / `--link-color`），所以换主题时整页一起变。
4. 首页对体验块只有一个 id（`#colamd-try`）和四个消息类型，别让首页去读框里的 DOM。

## 验过什么

| 检查 | 结果 |
| --- | --- |
| 内嵌形态 | 只有提示 + 「全屏」，主题栏 / 语言键 / 说明都收起来；编辑器在 350px 的框里自己滚 ✅ |
| 点「全屏」 | 首页加 `try-fullscreen`、锁滚动，框实测铺满 1440×900；主题栏与说明出现，按钮变「退出全屏」 ✅ |
| 退出 | 框内按 Esc、页面按 Esc 两条路都回到小块，两边状态一致 ✅ |
| 不重载 | 全屏来回切换时 iframe 的 `contentWindow` 是同一个对象，写过的内容不会被重置 ✅ |
| 语言联动 | 首页切英文，框里的样张、提示、按钮、iframe 标题一起变 ✅ |
| 输入 | 焦点在框内编辑器时，走真实输入管线写入文字成功，页面布局不受影响 ✅ |
| 横向溢出 | 414px 与 880px（历史上出过问题的那一档）实测 `scrollWidth === innerWidth`；桌面 1440 同样 ✅ |
| 居中窗口 | 独立页与全屏实测窗口 920×720、居中（1440 下左边 260）、正文列 780px；页面 `overflow: hidden`，窗口内 1579px 内容自己滚 ✅ |
| 说明文字 | 实测在窗口之下（窗口底 794，文字顶 808），居中；内嵌小块里不显示 ✅ |
| 细滚动条 | 编辑区 `offsetWidth - clientWidth` 实测 6px（默认浮层滚动条是 0，也就是看不出轨道）✅ |
| 手机 | 414px 下窗口铺满、描边与圆角归零，两侧无溢出 ✅ |

窄屏装饰框那 2px 的坑记在这里：`.editor-window::before` 自己旋转 -2.4 度，一个 370px 宽的面转过来右侧会多吃约 7px，所以 ≤860px 时它的 `inset` 只能留 1px 溢出量（留 18px 时整页会多出 2px，能左右晃动）。

## 已知取舍（MVP）

- 切换语言会重新载入样张，用户此刻改过的内容会被替换掉。要保留就得先做「是否已编辑」判断，这一版没做。
- 我在浏览器里验输入用的是浏览器的文本输入管线，不是逐键敲键盘；键盘手感要人自己敲一遍。
- 首页内嵌体验块的窄屏行为沿用站点的响应式规则（≤650px 时高度收到 260px），没有单独为它做适配。

## 上线方式

构建产物发到 gh-pages 的 `/try/`（`vite.web.config.ts` 里 `base: './'`，所以子路径可用），首页 `index.html` 里那段 iframe 与消息桥接也一并提交。当前是我本机 `npm run build:web` 后提交构建产物；接 CI 自动构建是后续的事。
