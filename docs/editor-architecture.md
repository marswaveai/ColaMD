# 编辑器架构：源码是唯一真相

本文说明一件事，以及它为什么能约束住一整类 bug。

## 一句话

**编辑器里存的是文件的字节。渲染是叠在字节上的一层装饰。**

由此推出一条硬纪律，它可以在 CI 里断言：

> **用户没改过的字节，保存时必须不变。**
> 判据：`save(open(x)) === x`。

## 为什么要有这条纪律

在引入它之前，编辑器的工作方式是：

```
文件 → 解析成文档树 → 丢掉原文 → 用户编辑树 → 重新序列化成文件
```

真相在树里。文件一旦被打开，它原来的样子就不存在了，保存时是从树重新「翻译」一遍。这个结构会产生三类故障，而且每一类都不是个别 bug，而是结构决定的：

1. **无谓改写**。序列化器不知道某个 `*` 是作者写的普通字符，只知道它可能引起歧义，于是加反斜杠：`3 * 4` 变成 `3 \* 4`。用户只改了一个字，整篇文件的标点却被动过。
2. **格式丢失**。行内公式的解析会把 `$...$` 区间当成原始文本读入，区间里的 `**加粗**` 从未被解析成加粗；当这段又被判定为「其实不是公式」而退回文本时，加粗已经不存在了。用户的加粗标记就此消失。
3. **静默损坏**。序列化时若需要原文位置信息（例如「这里原来用的是 `**` 还是 `__`」），而某些节点没有合法的源码位置，就会读到文档里毫无关系的一个字符，把它写进文件。这种错误没有任何征兆，直到用户打开文件才发现笔记被改坏。

三类故障的共同点：**症状出现在渲染层，伤害却落在文件上**。用户看到的是「这一段没渲染好」，代价却是稿子被改写。

把真相放回文本里，这三类故障全部消失：

| 问题 | 文本优先之后 |
|---|---|
| `3 * 4` → `3 \* 4` | 不存在：没改过的字节不参与任何写回 |
| `$5` → `\$5` | 不存在 |
| 表格分隔行 `---` 缩成 `-` | 不存在 |
| `**加粗**` 被吃掉 | 不存在：文本里的 `**` 一个都没动 |
| 需要探测原文件的标点风格再编回去 | 不需要：原文就在缓冲区里 |
| 需要把 YAML 属性区拆出来单独保管 | 不需要：它本来就是正文的一部分 |
| 需要「先解析成公式、再判定不像公式、再退回文本」 | 不需要：渲染规则只决定画不画，不决定写什么 |

右侧那一列，都是可以删除的代码。

## 结构

```
        ┌─────────────────────────────────────────┐
        │  CodeMirror 6 EditorView                 │
        │  state.doc 是 markdown 源码，就是文件的字节 │
        └─────────────────────────────────────────┘
                          │
      ┌───────────────────┼───────────────────┐
      │                   │                   │
  装饰层             输入规则             命令层
  (Decoration)      (InputRule)         (Command)
      │                   │                   │
  把源码画成             把用户的操作         加粗、列表、
  所见即所得             翻译成文本改动        格式切换
```

- **源码缓冲区**：CM6 的 `state.doc`，一个字符串。文件的字节进这里，出这里。
- **装饰层**：只负责画。把 `**x**` 画成加粗、把 `$x$` 画成公式、把表格画成表格、把 mermaid 画成图。装饰**不改变文本**，所以无论画错与否，文件都是安全的。
- **输入规则**：用户敲 `**bold**` 时，把「输入的这一段」翻译成一次已知区间的文本替换。不触碰区间之外的任何字节。
- **命令层**：`⌘B` 加粗的语义是「在选区两端插入 `**`」，不是「给节点加粗体标记」。前者是文本操作，可逆、可撤销、可预测。

## 一个必须守住的约束

**装饰层不许修改 `state.doc`。** 任何看起来需要「改写文本才能渲染」的需求，都要重新表达成「不改文本也能渲染」。这是这条架构唯一的纪律，也是它全部价值所在。

## 保存

保存不需要做任何事：

```
保存 = 把 state.doc 原样写回文件
```

不需要序列化、不需要风格探测、不需要属性区分流。用户的编辑已经以文本改动的形式落在缓冲区里了。

## 段落分隔与空段落

`paragraph-layout.ts` 用独立 StateField 收起顶层块之间的分隔换行，CSS 在相邻块之间计算留白。
文件里的零、一、两个分隔空行不会叠出整行高度；三个空行保留一个正常空段落。
代码、列表、引用内部的空行，以及属性区和块公式不参与这层替换。

替换区同时提供 `atomicRanges`，方向键和删除一次跨过分隔；事务过滤器负责搜索等程序化光标，
非空选区保留原始字节范围。空段落必须落在两组分隔换行之间，不能把全部隐藏字符堆到一侧，
否则打字后段落两边会得到不对称的源码换行。替换装饰只画不写，段落 Enter 才插入两个换行；
Shift+Enter、代码与列表输入沿用已有行为。源码模式使用独立文本区，不装这层规则。

验收：`node scripts/verify-paragraph-layout.mjs`，先构建，窗口用离屏壳启动。

## 源码什么时候露出来

装饰把标记藏起来，只留下渲染后的样子。但总得让人能改到标记本身，所以有一条规则：

> **行内标记一律不露源码；块级替换例外，光标进块就露。**

行内标记（`**`、`#`、`[]()` 这些）曾经是「光标所在的那一行露源码，且光标没有选中内容时才算」（2026-09-26 定的）；2026-10-06 取消：屏幕上不该为「偶尔改个标记」留一半噪音，要改标记去源码模式（`⌘/`）。这条收在 `live-preview.ts` 的 `isActiveLine` 里，它恒为 false。

块级替换（表格、图、HTML 块、块公式）是另一回事（2026-10-15 定，#153）：它们把**整段源码**换成渲染结果，光标落进去之后，打出来的字写进的是被盖住的源码。不露出来就是盲打 —— #153 报的就是「点表格某一格、打一个字，表格整块退回 markdown」。所以这些块的光标判据是 `isBlockActive`：光标落进块的区间就退回源码，点走再渲染回去（Obsidian 对表格就是这么做的）。另外，点在表格哪一格，光标就落到源码里那一格（`editor.ts` 的 `tableCellAnchor`）。

图片不在块级之列：它的源码只有一行，本来就贴在眼前，点一下排版要还在。

露出来的标记带 `cm-md-marker` 类并被压淡，和 Typora 一样。这个类不只是好看：它让复制和导出认得出「这不是正文」并把它丢掉。

**一个例外：有序列表的序号。** 它不走「光标在哪一行就露哪一行」这套，因为它是**改文件**的（见下）。

### 屏幕上的数就是文件里的数

编辑器会画很多东西——圆点、复选框、表格、公式，这些在文件里根本没有对应的字，全是从源码推出来的一层皮。序号不一样：**它就是文件里的那几个字符**。

曾经有一版把序号只改成「看起来对」的：文件里写着 `1. / 3. / 4.`，屏幕上画成 1、2、3。这被否了（2026-10-06，橘子的理由很直接）：屏幕一旦和文件不一样，复制出去、在 Obsidian 里打开、导出成纯文本，全都露馅——“文件是唯一真相”就是这么被卖掉的。

所以序号按规矩来：

> **增删列表项时，把序号写回文件；其余时候一个字都不动。**

- 写回发生在编辑的同一笔事务里（`compose` 到用户那笔改动后面），所以撤销一步就回到改前。
- 只在**列表项数量变了**（删一项、回车加一项、Tab 改层级、粘贴一整段）或**改到了序号本身**（改起始编号）时动手。
- 在列表里打普通文字不碰序号：有人故意把整列写成 `1.`，为的是 diff 干净（Typora 为此被人开过 issue）。
- 打开文件、外部写入、导出这些**程序化改动一律不碰**，「用户没碰过的字节不许变」照旧。
- 起点从第一项读（CommonMark 的 `<ol start>`）：`5.` 开头的列表重排后还是从 5 数起，导出到 HTML 也带着 `start`。

实现与两个坑在 `list-renumber.ts`。

## 已知的坑

八件都是**静默失效**：不报错，只是画得不对。写下来免得再烧一次。

- **装饰不许跨行替换**：用函数式 `EditorView.decorations.compute()` 提供的装饰命中跨行替换时会抛 `RangeError: Decorations that replace line breaks may not be specified via plugins`，整层装饰更新中断，表现是「整个界面错乱」。块公式、属性区、表格这类跨行替换必须由 `StateField` + `provide: (field) => EditorView.decorations.from(field)` 提供。
- **整块替换不要再叠同起点的空替换**：Mermaid 已把整个围栏换成图表，开头的 `CodeMark` 就不必再用空替换藏一次。两者起点相同时，退出源码编辑的增量更新可能只留下空 `span`，图表要滚出视口再回来才出现。只对非空、未在编辑的 Mermaid 块跳过围栏隐藏。回归网：`npm run verify:features -- --mermaid-only`。
- **不许在插件 `update` 里派发事务**：CM6 会报 `Calls to EditorView.update are not allowed while an update is in progress`，然后让那个插件直接崩掉，之后它不再更新。要派发就推到 `setTimeout` 里做。
- **语法树是按视口惰性解析的**：`syntaxTree(state)` 只覆盖已经解析过的那一段。装饰从树上读，所以滚到没解析过的区域时，那几行会以**原始源码**显示（`- **加粗**`），要点一下才会重算。视口移动时推一把解析（`forceParsing`）再请装饰重算一次。**推一次不够**：`forceParsing` 有时间预算，机器忙的时候一次推不到视口末尾，而不再有第二次的话就永远停在那儿了，表现为图片、公式、脚注、图表整片不渲染。要一直补到铺满为止（次数封顶）。回归网：`npm run verify:scroll-render`。
- **视口只渲染一屏**：CM6 只为视口附近的行建 DOM，其余用 `.cm-gap` 占位。任何把 DOM 当作「整篇文档」用的地方（导出、放映、复制）都必须先让整篇渲染出来（`ViewState.printing`），否则拿到的只有当前一屏。复制因此分两个口味：纯文本从文档本身取（`sliceDoc`，永远完整），HTML 只在选区确实落在已渲染范围里时才给；判「渲染出来了没有」看有没有 `.cm-gap`，不要看 `view.visibleRanges`，后者是「装饰没盖住的空隙」，不是「已经渲染的范围」。
- **CM6 自带的复制处理器排在插件处理器之后**：它在自己的处理器里 `clearData()` 再写纯文本，我们写在插件链里的 `text/html` 会被它清掉，返回 `true` 也拦不住。自定义复制要挂在**祖先元素**（`#editor`）的冒泡阶段。
- **语法着色的 tag 有继承关系，基准语法里多带的扩展会凭空染色**：`@codemirror/lang-markdown` 的 `markdownLanguage` 在 GFM 之外还带 Subscript、Superscript、Emoji 三个扩展，而这三个节点这个软件一个都不渲染。Emoji 尤其坑：它把「冒号 + 数字 + 冒号」也当 emoji 短代码（`@lezer/markdown` 的注释里明说不限字母、包括数字），于是时间轴里的 `00:00:17` 中间那段成了 `Emoji` 节点；而 `Emoji` 的 tag 是 `character`，`character` 又是 `string` 的**子标签**，正好命中代码块那条字符串着色规则，时间戳就绿了一段（2026-10-03 用户报的「时间轴出现绿字」）。判据是**只解析我们真的会渲染的东西**：基准语法用 CommonMark + GFM 自建，不要直接用 `markdownLanguage`。回归网：`npm run verify:features` 里的「时间戳不被当成 emoji 染色」。
- **点击被替换掉的块：判据是「空光标」，不是「拉出选区」**：块级替换（表格、图、HTML 块、块公式）点一下要能回到源码里改，做法是在 widget 上带自己的源码区间，点击时把光标放进去（见 `live-preview.ts` 的 `withSourceRange` 与 `editor.ts` 的点击处理器）。但**选中整段是不行的**：拉出选区反而让块继续藏着（`isBlockActive` 只认整段落在块里的选区，2026-10-03 踩过）。表格另外按点到的格算：同样在 `editor.ts`，`tableCellAnchor` 把行、列映到源码里那一格，行号要记得跳过源码里那行分隔行。另外每个 widget 的 `eq()` 必须把区间也算进去：不算的话，在上面插入一行后 widget 会被当成没变而复用，带着旧的区间，点下去光标落到别的地方。

## 与外壳的关系

编辑器的对外接口保持不变（见 `editor.ts` 的导出）。标签、文件面板、大纲、导出、主题、IPC 都不需要知道内部换了实现——它们只认那几个函数。因此这次替换是局部的：外壳不动，核心重写。
